# TgAnnouncer v0.1

Персональный Telegram-бот для одноразовых напоминаний. Python 3.12+, aiogram 3,
aiosqlite, SQLite и python-dotenv. Работает одним процессом без внешних сервисов.

## Настройка и запуск

1. В Telegram откройте **@BotFather**, отправьте `/newbot`, задайте имя и username.
   Скопируйте выданный токен в `BOT_TOKEN`. Не публикуйте токен.
2. Узнайте свой числовой Telegram ID: например, отправьте `/start` боту
   **@userinfobot** и возьмите поле `Id`. Это `OWNER_ID`, а не username или телефон.
3. Создайте `.env` рядом с `bot.py`, скопировав `.env.example`:

   ```dotenv
   BOT_TOKEN=123456789:токен_от_BotFather
   OWNER_ID=123456789
   TIMEZONE=Asia/Bangkok
   ```

   `TIMEZONE` — имя IANA, например `Europe/Moscow`, `Europe/Berlin`, `Asia/Bangkok`
   или `UTC`. Все параметры обязательны. Переменные окружения имеют приоритет
   над `.env`. `tzdata` обеспечивает работу часовых поясов на Windows.

4. В каталоге проекта установите зависимости и запустите бота:

   ```bash
   python -m venv .venv
   # Windows PowerShell:
   .venv\Scripts\Activate.ps1
   # Linux/macOS: source .venv/bin/activate
   pip install -r requirements.txt
   python bot.py
   ```

5. Откройте личный чат с созданным ботом и отправьте `/start` от имени владельца.
   Это необходимо, чтобы Telegram разрешил боту писать вам. Управление доступно
   только `OWNER_ID` и только в личном чате; сообщения остальных пользователей игнорируются.

## Использование

- **Создать напоминание** → непустой текст до 1000 символов → дата и время
  строго в формате `ДД.ММ.ГГГГ ЧЧ:ММ`, например `31.12.2027 18:30`.
- Ввод и отображение используют `TIMEZONE`; SQLite хранит даты в UTC.
  Прошедшее время, некорректные даты, несуществующее и неоднозначное местное время
  при переводе часов отклоняются. Для последних выберите другое время.
- **Отмена** или `/cancel` отменяют создание; `/start` возвращает меню.
- **Мои напоминания** показывает активные записи по времени. **Удалить** открывает
  подтверждение: **Да, удалить** / **Отмена**.

## Хранение и доставка

Файл `reminders.sqlite3` создаётся автоматически рядом с `bot.py`. Таблица
`reminders` содержит `id`, `text`, `remind_at`, `status` (`pending`/`sent`),
`created_at`. Для переноса данных сохраните этот файл при остановленном боте.
Текст отправляется без HTML/Markdown-разметки.

Проверка наступивших напоминаний выполняется каждые 5 секунд. Успешная отправка
меняет статус на `sent`; отправленные записи не показываются в активных.
При ошибке напоминание остаётся `pending`, повтор выполняется не раньше чем
через 60 секунд. При ограничении Telegram учитывается также `retry_after`.
Ошибки SQLite и Telegram обрабатываются без остановки работающего бота.
Ошибки конфигурации, подключения при запуске или открытия базы требуют исправления
и повторного запуска.

Приложение должно оставаться запущенным, компьютер — включённым с доступом в интернет.
После запуска просроченные активные напоминания отправляются сразу.
Напоминания переживают перезапуск, незавершённый FSM-диалог — нет.
Задержки повторов хранятся в памяти и после перезапуска сбрасываются.
Запускайте только один экземпляр бота для одного токена и базы.

Возможен дубль при обрыве связи после приёма сообщения Telegram или аварийном
завершении между отправкой и записью `sent` в SQLite: эти операции не атомарны.
При ошибке записи `sent` в работающем процессе повторяется только запись в базу.
Удаление ждёт завершения уже начавшейся отправки; после успешного удаления
новая отправка этого напоминания не начнётся.

## Проверки

Без настоящего токена и подключения к Telegram:

```bash
python -m unittest discover -s tests -v
python -m compileall -q bot.py config.py database.py reminders.py tests
pip check
```

Тесты используют временную SQLite и настоящий диспетчер aiogram с подменённым
транспортом Telegram. Проверяются создание через FSM, валидация, отмена, доступ,
список, подтверждение удаления, сохранение после переоткрытия базы, отправка,
повторные попытки, ограничения Telegram и ошибки SQLite.

Для ручной проверки создайте напоминание на ближайшую будущую минуту, перезапустите
процесс до срока и дождитесь сообщения. Затем проверьте отмену удаления и удаление
второго напоминания, а также отсутствие меню у другого Telegram-пользователя.

Файлы: `bot.py` — меню, FSM и запуск; `config.py` — настройки;
`database.py` — SQLite; `reminders.py` — даты и отправка.
API диспетчера: [официальная документация aiogram](https://docs.aiogram.dev/en/latest/dispatcher/dispatcher.html).

## Сервер Ubuntu / systemd

Приложение размещается в `/opt/tgannouncer`, виртуальное окружение —
`/opt/tgannouncer/.venv`. Служба работает под отдельным системным пользователем
`tgannouncer` без интерактивного входа. Шаблон службы: `deploy/tgannouncer.service`.
Пароль SSH в проекте не хранится.

На сервере нужен Python 3.12+ с модулем `venv`. После установки зависимостей
поместите `.env` и базу `reminders.sqlite3` в каталог приложения. Для переноса
существующей базы используйте SQLite backup API или копируйте её при остановленном
локальном боте. Каталог и данные должны быть доступны пользователю `tgannouncer`;
права `.env` — `600`, каталога — `750`.

Установка подготовленного файла службы (от root):

```bash
install -m 644 /opt/tgannouncer/tgannouncer.service /etc/systemd/system/tgannouncer.service
systemctl daemon-reload
systemctl enable --now tgannouncer
```

Управление на сервере:

```bash
systemctl status tgannouncer --no-pager
journalctl -u tgannouncer -n 50 --no-pager
systemctl restart tgannouncer
systemctl stop tgannouncer
```

Служба запускается после загрузки сервера и перезапускается через 15 секунд
после завершения процесса. Ручная команда `systemctl stop` оставляет её остановленной.
Настройки systemd описаны в [официальном руководстве](https://www.freedesktop.org/software/systemd/man/255/systemd.service.html).
Для long polling не нужны домен, HTTPS и открытые входящие HTTP-порты.
Во время работы серверного экземпляра не запускайте локальный бот с тем же токеном.
